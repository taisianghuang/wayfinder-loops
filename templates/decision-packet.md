# 決策封包 template

非同步化之後每次來回成本是幾小時,所以每則封包必須能自足決策。
用決策樹取代單一問題,把 5 個 round trip 壓成 1–2 個。

選項數紀律:超過 3 個選項先找正交的軸拆成兩層決策;真的攤平的同儕選項
(vendor 挑選這類)照列 A–E,但「怎麼回覆」改成「留言回選項字母」——label
只開到 c;超過 5 個候選先開 `wayfinder:research` 收斂 shortlist 再開票。

---

```markdown
## 決策:<一句話的問題>

**為什麼現在需要決定**
<它會鎖住什麼、影響哪些檔案 / API contract>

**選項**
| | 做法 | 代價 | 之後會變簡單 | 之後會變難 |
|---|---|---|---|---|
| A | | | | |
| B | | | | |
| C | | | | |

**我的建議:<X>**
<理由,盡量引用 repo 內既有的 ADR / GLOSSARY.md / 程式碼作為根據>

**如果你選 A,下一個問題會是**:<...>(我的建議:...)
**如果你選 B,下一個問題會是**:<...>

**怎麼回覆**
加上 `decision:a` / `decision:b` / `decision:c` / `decision:approve` label,
或直接留言。有疑慮就加 `decision:discuss`。
```
